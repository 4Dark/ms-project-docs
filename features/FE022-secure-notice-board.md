# FE022: 通用安全公告栏与通知中心 (Secure Notice Board)

## 1. 业务背景
为了在微信等社交平台上安全地分享敏感链接（如包含时效性的订阅地址或工具配置），同时防止这些内容被自动化机器和平台审查机制抓取和封锁，我们需要一个专属的防爬虫分享单页。

## 2. 核心架构设计与边界划分
根据安全性需求和架构精简原则：
1. **身份认证与人机验证（边界防御）**：全部交由 **Cloudflare Zero Trust** 网关完成。系统无需在前后端代码中编写 Turnstile 或提取码逻辑。经过 CF 放行的流量，对应用服务而言即视为“已通过初步安全过滤的访客”。
2. **应用系统（业务展示与管理）**：
    - `ms-ng-view` 前端只负责将已拉取到的敏感信息（Notice Board Items）与系统公告（Announcements）渲染出来。
    - `ms-java-biz` 提供 REST 接口用于信息的存取，并根据 Casdoor JWT 中的 `admin` 角色判定管理权限。

## 3. 功能需求

### 3.1 访客视角 (Visitor)
*   **浏览公告**：进入页面，顶部展示最新的系统公告卡片（标题、内容与发布时间）。
*   **浏览敏感链接**：底部以表格展示可用的敏感资源（按客户端/分类分组）。展示内容包括目标客户端、说明、参考地址以及核心分享链接。
*   **一键复制**：针对核心分享链接，提供“一键复制”交互，点击后触发后端查看/复制事件统计。
*   **单条公告详情页**：提供独立的单页用于查看单条公告（路由如 `/#/notice-board/a/:id`）。该页面受“全局提取码”保护，访客必须输入正确的密码才能查看。内容将使用 Markdown 引擎进行全功能渲染排版。

### 3.2 管理员视角 (Admin)
拥有 Casdoor `admin` 角色的用户，将在统一页面内看到：
*   **新增公告按钮**：弹出对话框录入新公告。
*   **新增敏感链接按钮**：弹出对话框录入敏感资源，并设定其过期时间 (`expire_time`)。

## 4. 后台自动化处理
*   数据过期自动清理：后端配置 `@Scheduled` 定时任务，周期性删除超过设定 `expire_time` 的敏感资源，以确保泄露的链接也不会永远存活。
*   **全局提取码验证**：后端服务预先配置全局提取码（`dark.notice-board.extraction-code`），前端在请求单条公告时，通过 Headers （如 `X-Extraction-Code`）进行安全校验。

## 5. 交互协议与数据模型
- 具体 API 接口设计参考 `MsJavaBiz-SecureNoticeBoard-v1.yaml`。
- 采用双表设计：`ms_notice_board_item` 与 `ms_announcement` 分别存储链接项和公告。
